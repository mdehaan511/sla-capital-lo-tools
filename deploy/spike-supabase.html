Supabase Auth Spike

Proves end-to-end: @supabase/supabase-js from CDN (no bundler) → magic-link login → JWT verified by _shared/supabase-auth.mjs in a Netlify Function.

1. Config check

Supabase URL and publishable key are baked into this page. The JWT secret + service role live in Netlify env only.

Client SDK: loading… Session: none
If the SDK pill stays red, the CDN load failed — see console.

2. Send magic link

Enter an email → Supabase sends a login link → clicking it redirects back here with an access token in the URL hash → we complete the session.

3. Call spike API with JWT

Hits /api/spike-supabase-echo with Authorization: Bearer <access_token>. The function verifies the signature with SUPABASE_JWT_SECRET and echoes what it saw. Green = round-trip works and the migration mechanic is proven.

Notes

      
What this proves: JWT signature verification works with pure Node crypto (no jsonwebtoken dep), vanilla-JS integration works via CDN ESM (no build step), magic-link + email-confirm-off works out of the box.

      
Next question: role assignment on invite. The service-role key (server-only) can call admin.inviteUserByEmail(email, { data: { role: 'processor' } }) from a Netlify Function — that's the pattern for the in-app "Invite user with role" flow once we commit.

      
What's not proven yet: (a) importing existing LO users from Netlify Identity without re-inviting, (b) session refresh behavior on tab-switch after 1hr token expiry, (c) rate-limit behavior on magic-link sends. Not blockers, but worth prototyping before a real migration.
